## 🎨 Padrões Estabelecidos

### Arquitetura de Navegação

```
SocialAppFeature (Composition Root)
├── Gerencia estado global de navegação
├── Orquestra transições entre Features
├── Mantém sincronização entre Features
└── Gerencia tabs e navigation stack
```

### Tipos de Navegação

1. **Tab Navigation**: Entre seções principais
2. **Modal/Sheet Navigation**: Detalhes sobre conteúdo
3. **Navigation Stack**: Hierárquica dentro de Feature
4. **Deep Linking**: (Estrutura preparada para futuro)

### Padrões de Navegação

1. **Navegação Simples (Tab)**: `tabSelected(AppTab)`
2. **Navegação para Detalhe (Modal)**: `navigateToDetail(UUID)`
3. **Navegação com Dados**: Carregar dados antes de navegar
4. **Navegação Cross-Feature**: Delegate pattern
5. **Navegação com Sincronização**: Sync actions entre Features

### Transições Recomendadas

| Tipo | Transição | Uso |
|------|-----------|-----|
| Tab change | `.fade` | Home → Tickets |
| Modal/Sheet | `.slideFromBottom` | EventDetail, TicketDetail |
| Fullscreen | `.scaleWithFade` | AddTicket, Auth |
| Navigation Stack | `.move(edge: .trailing)` | Settings → Privacy |
| Cross-Feature | `.slideFromBottom` | Ticket → Negotiation |

## 📖 Decisões Técnicas

### 1. Composition Root Pattern
**Decisão**: SocialAppFeature gerencia toda navegação.

**Razão**:
- Centraliza lógica de navegação
- Facilita sincronização entre Features
- Permite deep linking futuro
- Facilita testes

### 2. Delegate Pattern para Cross-Feature
**Decisão**: Features usam delegate para navegar para outras Features.

**Razão**:
- Desacopla Features
- SocialAppFeature orquestra navegação
- Facilita manutenção
- Padrão comum em TCA

### 3. State Opcional para Modals
**Decisão**: Features de detalhe são opcionais no state.

**Razão**:
- SwiftUI `.sheet(item:)` requer Optional
- Facilita dismiss (nil = fecha)
- Melhor performance (não mantém state quando não visível)

### 4. Sincronização Explícita
**Decisão**: Navegação que afeta múltiplas Features usa sync actions.

**Razão**:
- Garante consistência de dados
- Evita desincronização
- Facilita debugging
- Melhor UX (dados atualizados)

## 🎓 Aprendizados e Guidelines

### Boas Práticas Documentadas

1. **Sempre limpar state ao dismiss**: Evita memory leaks
2. **Usar delegate pattern**: Desacopla Features
3. **Sincronizar dados**: Mantém consistência
4. **Usar transições DS**: Consistência visual
5. **Documentar fluxos complexos**: Facilita manutenção

### Anti-Patterns Documentados

1. ❌ Navegar diretamente entre Features
2. ❌ Esquecer de limpar state
3. ❌ Usar NavigationLink diretamente
4. ❌ Não sincronizar dados
5. ❌ Ignorar transições
