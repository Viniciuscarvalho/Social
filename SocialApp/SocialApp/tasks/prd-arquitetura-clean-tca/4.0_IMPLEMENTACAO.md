**Tamanho:** Médio/Grande (M/L)

## Resumo Executivo

Criei com sucesso a camada **Data** separada, estabelecendo uma arquitetura limpa onde:
- **Data** conhece **Domain** (importa modelos de domínio)
- **Domain** NÃO conhece **Data** (separação unidirecional)
- DTOs de API ficam isolados na camada Data
- Mappers claros (`toDomain()`) convertem DTOs → Domain

## Exemplo de Uso (Clients TCA)

```swift
// UserClient.swift
import Dependencies
import Domain
import Data

extension UserClient: DependencyKey {
  public static let liveValue = UserClient(
    fetchUser: { userId in
      let dto: APIUserResponse = try await networkService.get("/users/\(userId)")
      return dto.toUser() // ← Mapper Data → Domain
    }
  )
}
```

## Desafios Enfrentados e Soluções

### 🚨 Problema: Arquivo APIModels.swift Muito Grande
**Sintoma:** 3092 linhas com dezenas de DTOs misturados

**Solução:** Migração incremental
- Task 4.0: Criar estrutura e migrar DTOs principais
- Continuação: Migrar restante conforme necessário
- Documentar o que falta migrar

### 🚨 Problema: Compatibilidade camelCase/snake_case
**Sintoma:** API retorna campos em formatos diferentes

**Solução:** Computed properties
```swift
let profileImageURL: String?
let profile_image_url: String?

var finalProfileImageURL: String? {
  return profileImageURL ?? profile_image_url
}
```

### 🚨 Problema: Parsing de Datas Flexível
**Sintoma:** API retorna datas em múltiplos formatos

**Solução:** Helper com array de formatos
```swift
let dateFormats = [
  "yyyy-MM-dd'T'HH:mm:ss.SSSZ",
  "yyyy-MM-dd'T'HH:mm:ssZ",
  "yyyy-MM-dd"
]
```
