# Migração da ProfileFeature - Análise e Plano

## Status: 📋 PLANEJADO

Data: 27 de novembro de 2025

## Análise da Feature Atual

### Arquivos
- ✅ `ProfileFeature.swift` - Feature TCA (215 linhas)
- ⚠️ `ProfileView.swift` - View principal (831 linhas - muito grande!)

### State Atual

**✅ Pontos Positivos:**
- Já usa tipos do Domain (`User`)
- Já tem `@ObservableState`
- State bem organizado
- Usa `@Dependency` para clients

**⚠️ Pontos a Melhorar:**
- Actions não estão organizadas por categoria
- Falta `Equatable` em `Action`
- Falta derived state (computed properties)
- Usa `NotificationCenter` para navegação (deveria usar delegate pattern)

### Actions Atual

```swift
public enum Action {  // ❌ Falta Equatable
    case onAppear
    case loadUserProfile
    case loadTicketsCount
    case userProfileResponse(Result<User, NetworkError>)
    case ticketsCountResponse(Result<Int, NetworkError>)
    
    // UI Actions
    case editProfileTapped
    case changeProfileImageTapped
    // ... muitas actions sem organização clara
}
```

**Problemas:**
- ❌ Não tem `Equatable`
- ❌ Actions não organizadas por categoria
- ❌ Navegação via `NotificationCenter` (linha 130-134)
- ⚠️ Algumas actions não têm implementação (supportTapped, privacySettingsTapped, signOutTapped)

### View Atual

**❌ Problemas Identificados:**
1. Usa `AppColors` (antigo) ao invés de `DSColors`
2. Usa `ThemeManager` (antigo) ao invés de `DesignSystem Theme`
3. Componentes customizados que poderiam usar DS:
   - `menuRow` → `DSListCell`
   - `sellerCardView` → `DSCard`
   - `profileHeaderView` → `DSCard` com layout customizado
4. Não usa componentes do Design System
5. Não usa transições do Design System
6. View muito grande (831 linhas) - deveria ser quebrada em subviews

**Componentes a Substituir:**
| Atual | Substituir por |
|-------|----------------|
| `AppColors.*` | `DSColors.*` |
| `ThemeManager` | `DesignSystem.ThemeManager` |
| `menuRow` | `DSListCell` |
| `sellerCardView` | `DSCard` |
| `ProgressView()` | `DSLoadingIndicator` |
| Custom cards | `DSCard` |
| Custom buttons | `DSButton` |

## Plano de Migração

### Fase 1: Refatorar ProfileFeature (Reducer)

#### 1.1 Organizar Actions
```swift
public enum Action: Equatable {  // ✅ Adicionar Equatable
    // MARK: - Lifecycle
    case onAppear
    case onDisappear
    
    // MARK: - Data Loading
    case loadUserProfile
    case loadTicketsCount
    case userProfileResponse(Result<User, NetworkError>)
    case ticketsCountResponse(Result<Int, NetworkError>)
    
    // MARK: - User Interactions
    case editProfileTapped
    case changeProfileImageTapped
    case myTicketsTapped
    case favoritesTapped
    case themeSelectionTapped
    case supportTapped
    case privacySettingsTapped
    case signOutTapped
    case togglePushNotifications(Bool)
    
    // MARK: - Navigation
    case setShowingEditProfile(Bool)
    case setShowingImagePicker(Bool)
    case setShowingMyTickets(Bool)
    case setShowingFavorites(Bool)
    case setShowingThemeSelection(Bool)
    case delegate(Delegate)  // ✅ Novo: delegate pattern
    
    // MARK: - Profile Update
    case updateProfile(User)
    case updateProfileResponse(Result<User, NetworkError>)
    
    // MARK: - Ticket Management
    case ticketDeleted
    case ticketCreated
    case refreshMyTickets
    case myTicketsSheetClosed
    
    // MARK: - Error Handling
    case dismissError
    
    // MARK: - Delegate
    public enum Delegate: Equatable {
        case navigateToSellerProfile(String)
        case navigateToEventDetail(UUID)
    }
}
```

#### 1.2 Adicionar Derived State
```swift
@ObservableState
public struct State: Equatable {
    // ... existing state ...
    
    // MARK: - Derived State
    public var displayName: String {
        user?.name ?? "Usuário"
    }
    
    public var hasTickets: Bool {
        ticketsCount > 0
    }
    
    public var isSeller: Bool {
        hasTickets
    }
}
```

#### 1.3 Substituir NotificationCenter por Delegate
```swift
// ❌ Antes
case let .navigateToSellerProfile(sellerId):
    NotificationCenter.default.post(...)
    return .none

// ✅ Depois
case let .navigateToSellerProfile(sellerId):
    return .run { send in
        await send(.delegate(.navigateToSellerProfile(sellerId)))
    }
```

#### 2.4 Substituir Componentes Customizados

**menuRow → DSListCell:**
```swift
// ❌ Antes
menuRow(icon: "qrcode", ...) { ... }

// ✅ Depois
DSListCell(
    icon: "qrcode",
    iconColor: DSColors.accentGreen,
    title: "Ingressos",
    subtitle: "Seus ingressos e QR Codes",
    accessory: .chevron
) {
    store.send(.myTicketsTapped)
}
```

**sellerCardView → DSCard:**
```swift
// ❌ Antes
sellerCardView(user: user)

// ✅ Depois
DSCard {
    HStack(spacing: DSSpacing.sm) {
        DSIconBadge(icon: "person.badge.shield.checkmark.fill", style: .primary)
        VStack(alignment: .leading) {
            Text("Perfil de Vendedor")
                .font(DSTypography.headline())
            Text("\(user.ticketsCount) ingressos disponíveis")
                .font(DSTypography.footnote())
        }
        Spacer()
        Image(systemName: "chevron.right")
    }
}
```

**Loading → DSLoadingIndicator:**
```swift
// ❌ Antes
ProgressView()
    .foregroundColor(AppColors.primaryText)

// ✅ Depois
DSFullScreenLoading(message: "Carregando perfil...")
```

#### 2.5 Adicionar Transições
```swift
// ✅ Adicionar transições do Design System
.sheet(isPresented: $store.showingEditProfile) {
    editProfileSheet
        .dsTransition(.slideFromBottom)
}
```

#### 2.6 Quebrar View em Subviews
```swift
// ✅ Organizar em subviews menores
@ViewBuilder
private var contentView: some View {
    if store.isLoading && store.user == nil {
        loadingView
    } else {
        ScrollView {
            VStack(spacing: DSSpacing.l) {
                profileHeaderView
                if store.hasTickets {
                    sellerCardView
                }
                menuSection
                footerView
            }
            .padding(DSSpacing.m)
        }
    }
}
```
