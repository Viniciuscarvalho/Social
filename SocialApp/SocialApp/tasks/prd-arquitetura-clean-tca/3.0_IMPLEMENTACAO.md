## Princípios Seguidos

✅ **Domínio Puro**
- Nenhuma dependência de SwiftUI, NetworkService ou frameworks externos
- Apenas `Foundation` para tipos básicos

✅ **Organização por Contexto**
- Cada arquivo agrupa modelos relacionados por contexto de negócio
- Facilita navegação e manutenção

✅ **Value Semantics**
- Uso exclusivo de `struct` e `enum` (não `class`)
- Conformidade com `Codable`, `Identifiable`, `Equatable`
- Modelos thread-safe marcados como `Sendable`

✅ **Código Limpo**
- Indentação de 2 espaços (seguindo Kodeco Style Guide)
- MARK comments para separar seções
- Computed properties mantidas com lógica de negócio

## Desafios Enfrentados e Soluções

### 🚨 Problema: Espaço em Disco Insuficiente
**Sintoma:** Erro "ENOSPC: no space left on device" ao criar arquivos

**Solução:** Aguardei liberação de espaço (de 115MB para 14GB disponível), então retomei a criação dos arquivos

### 🚨 Problema: Tipos Duplicados
**Sintoma:** Modelos de domínio existentes tanto nos novos arquivos quanto em `Models.swift`

**Solução:** Renomeei `Models.swift` → `APIModels.swift` temporariamente. Os DTOs serão movidos para a camada Data na Task 4.0
